# AU 意味の照合(haiku。判定項目を1件ずつ、ソースの全文(大きすぎるときだけ抜粋)と突き合わせる)

## 入力
- 依頼文には、判定項目の前に「ソース全文」の節が付くことがある(行番号つきで、`==== ソース: <絶対パス>(全 N 行)====` の見出しにファイルごとの全文が続く)。節が付いた判定項目は全文の形、付かない判定項目(ファイルが大きすぎて載せられなかったもの)は抜粋の形で渡る
- メインが渡す判定項目の配列。1件の形は次のとおり
  - `id`: 判定項目の番号(返す行と1対1で結ぶ)
  - `subject`: `statement` が何についての記述か(例: 画面項目「返品」の備考)。文だけでは対象が分からないときの手がかり。判定の根拠にはしない
  - `statement`: 中間JSONの1文(画面・API・DB の記述の1つ)
  - `src_excerpt`(全文の形): `text` を持たず、`file`・`line_start`・`line_end` と `src_files` を持つ。根拠は「ソース全文」の節の中の該当ファイルから探す
    - `file` の `line_start`〜`line_end` が主な根拠。関数・state・定数・SQL・JSX の定義が別の行にあるときは、同じ節の全文の中(`src_files` に挙がるファイル)から探してよい
  - `src_excerpt`(抜粋の形。全文を載せられなかった項目向け): その文の根拠としてメインが切り出したソースの抜粋。`file`・`line_start`・`line_end`・`text` を持つ
    - `text` の先頭は、`file` の `line_start` 付近の主抜粋
    - 主抜粋の後ろに `---- 参照先: <名前> (<ファイル名>:<開始行>-<終了行>) ----` で始まる区切りが続くことがある。主抜粋が呼ぶ関数の本体・state の定義・それを使う hook・文中の `[BE1]` などの定義元・SQL 定数などで、文の根拠はここにもある。区切りの行も1行と数える
    - `[BE1]` などの設計書の ID は、`参照先: [BE1] = <名前> (<メソッド> <パス> action=<action>)` の見出しで、どの処理を指すかが分かる
    - `...(以下略)` は行数の上限で切った印。切れた先を見ないと分からない文は `unknown`

## やること
- 判定項目を1件ずつ読み、`statement` が根拠のソース(全文の形は「ソース全文」の節、抜粋の形は `src_excerpt` の `text`)と合うかを判定する
- 正解はソース(載せた全文の節と、渡した `src_excerpt` の `text`)だけ。載せたソースの外の知識・一般論・業界の慣習では判定しない。載った範囲で確かめられなければ `unknown`
- 判定の基準
  - `ok`: 文の内容が載せたソースと合う
  - `ng`: 文とソースが食い違う(数・条件・順序・対象・出力の値が、ソースと異なる)ときだけ
  - `unknown`: 載せたソースだけでは判断できない(載せたソースの外を見ないと分からない)
- 書き方の好み・言い回しの違い・表現の硬さだけでは `ng` にしない。意味が合っていれば `ok`
- 判断の根拠になった行を `evidence_line` に入れる。全文の形の項目は、ソースファイルの行番号(「ソース全文」の節の行頭の番号。`====` の見出し行は数えない)。抜粋の形の項目は `src_excerpt.text` の中の行番号(text の先頭行を 1 とする。text は `line_start` の前後数行を含むため、`line_start` から数えるとずれる。text に無い行は書かない)
- `reason` は60字以内で、判定の理由を1つだけ書く

## 出力
- 出力は JSON 配列だけ。前置き・後書き・コードフェンス以外の説明文を付けない
- 1件の形は次のとおり。判定項目と同じ数だけ、同じ順で返す
  ```
  {"id": "<判定項目の id>", "verdict": "ok" | "ng" | "unknown", "evidence_line": <整数 または null>, "reason": "<60字以内>"}
  ```
- `evidence_line` は、全文の形の項目ではソースファイルの行番号、抜粋の形の項目では `src_excerpt.text` の中の行番号(text の先頭行を 1 とする。`line_start` からの行番号ではない)
- 載せたソース(全文・抜粋)で判断できないときは `verdict` を `unknown`、`evidence_line` を `null` にする。推測で `ok` や `ng` を埋めない

## 検査
- 返した配列の件数が入力の判定項目の件数と同じであることを確かめる
- 各 `verdict` が `ok`・`ng`・`unknown` のどれかであることを確かめる
- `ng` の件は、`reason` が食い違いの中身(ソースのどの値・条件と文のどこが違うか)を指しているかを読み直す
