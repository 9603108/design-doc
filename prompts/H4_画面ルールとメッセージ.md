# H4 画面ルールとメッセージの写し(haiku)

## 入力
- 画面のソース(入力チェック・計算の式)、バックエンドの validation とメッセージの定義
- `07_バリデーション.md`(必要な節だけ)

## 書く欄(`_unit_H4.json`。messages_backend の行を作る)
- `no`(validations_frontend・calculations の通し番号)は書かない。合成が並び順で振る
- `validations_frontend[]`: {field, rule, applied_when, kind, message_id}
  - field は画面項目の名前(S1 の item_name と同じ字面)。並びは 必須 → 形式 → その他
  - ソースのチェックを1つずつ写す。field・rule・applied_when を全部空にしない
  - `kind` は処理の種別を次の4つから1つ書く: 入力検査 / 表示切替 / 活性切替 / 絞り込み
    - 処理の種別を照合する: ソースの書き方で決める。入力値を調べてエラーにする(`if (…) { setError(…) }`・throw・input の required/min/max/pattern/maxLength)だけが 入力検査
    - 条件で表示を出し分ける(`{cond && <…>}`・三項)は 表示切替、`disabled={…}` は 活性切替、`.filter(` で行や項目を絞るのは 絞り込み。表示切替を入力検査と書かない
    - 画面のソースに入力検査が無い(日付の形式検査がバック側にあるだけ等)ときは、入力検査の行を書かない
- `calculations[]`: {name, formula, inputs[{name, source}], outputs[{name, destination}], remarks}
  - formula はソースの式を業務の言葉に写す。端数・0 除算・NULL の扱いは remarks
- `messages_backend[]`: {message_id, code, severity, message, emitted_by_api[]}
  - code は message_id と同じ ID(MSE00001 の形)。severity は error / warning / info
  - 画面とバックエンドが出すメッセージを全部。S2 の error_patterns の message_id もここに必要
  - `message` はソースの文字列を一字一句そのまま写す。バックの文面は下書きの error_patterns の `text_expanded`(`from は YYYY-MM-DD 形式で指定してください` の形。`validation_error:` などの前置きも `{key}` も画面項目名への言い換えもしない)。下書きの同じ ID の `text_expanded` が複数あれば、文面ごとに1行ずつ書く(`from` と `to` と `shop_id` は別の行)
  - 言い換え(「集計開始日が日付の形式でない」)は S2 の condition に書く。message には書かない(ソースの文字列に無い文言は verify_vs_source が差し戻す)

## 書かない欄
- common_logic(S1)、error_patterns(S2)
