# S0 画面の設定(sonnet。並行の単位より先に1回)

screen_config が雛形のまま、または下の欄が空のときだけ動く。他の単位は画面名とエリア名をここから読む。

## 入力
- 画面のソース(screen_config の `source_files` か `source_html_path`)、`{機能名}_react_draft.json`(React のときだけ)
- `examples/sample/受注入力_screen_config.json`(書き方の見本)、`03_初期処理.md`

## 書く欄(`target/intermediate/{機能名}_screen_config.json` を直接書く)
- `screen_name`(「〜画面」で終わる正式名)、`areas[]`(area_no / area_name / screen_no / description。裏方領域は screen_no "0")
- `process_names_by_event_code`(EV01… → フロント処理の名前)、`process_overview_overrides`
- `initial_processes.processes[]`(初期表示の steps・preconditions・postconditions。backend_call.backend_id は api_spec の並び順の B001 形式)
- `trigger_dispatch`(EV00 の dispatch。URL パラメータの判定はここで完結させ、初期処理の steps に書かない)

## 業務の判断が要る所(この単位が sonnet である理由)
- 画面の概要と業務の中心概念(例: 取込欠損をどう判定するか)を、areas の description と初期処理の postconditions に書く
- エリアの切り方は、業務担当者が画面をどう読むかで決める

## 検査
- `python3 -m json.tool target/intermediate/{機能名}_screen_config.json >/dev/null` が通ること
