# S3 フロント処理のステップ(sonnet)

## 入力
- `{機能名}_react_draft.json` の `event_processes`(呼出の行「・<action> をリクエストする」と、未記入の印)
- 画面のソース(各イベントのハンドラ)、`04_機能別処理.md` の「details の書き方」

## 書く欄(`_unit_S3.json`)
- `event_processes[]`: {event_code, details[], details_none_reason}。EV00(初期表示)は書かない(S0 の initial_processes)
  - details は処理ステップを1行1 step で、業務担当者の語彙で書く
  - 下書きの呼出の行は**字面も並びもそのまま残す**(apply_react_draft.py --stage merge が数と並びを照合する)
  - 呼出の行以外に「呼出」「API」「リクエスト」「fetch」「POST」「GET」の語を書かない(呼出と数えられて割り当てがずれる)
  - 未記入の印「（未記入）この行を…」は残さない
  - **異常系の判断が仕事**: 入力が不正・取得に失敗・0件のとき、画面が何をするかをソースから読んで行にする
- 下書きが無い画面(HTML)は、イベントごとに呼ぶ API を、ソースの呼出の順に「・<action> をリクエストする」で書く

- 下書きの `continuous_operation` に事実があるときは、連続操作の行に書く(事実が無ければ書かない)
- 取消・防止などが無いことも、ソースで確かめた事実として書く(根拠は該当箇所に無いこと)。例: prevention が「防止なし」なら「読込中の再操作を防ぐ仕組みは無い」と書く

## 書かない欄
- events の trigger・content(H1)。overview は events の content から作られる
