# S3 フロント処理のステップ(sonnet)

## 入力
- `{機能名}_react_draft.json` の `event_processes`(呼出の行「・<action> をリクエストする」と、未記入の印)
- 画面のソース(各イベントのハンドラ)、`04_機能別処理.md` の「details の書き方」

## 書く欄(`_unit_S3.json`)
- `event_processes[]`: {event_code, details[], details_none_reason}。EV00(初期表示)は書かない(S0 の initial_processes)
  - details は処理ステップを1行1 step で、業務担当者の語彙で書く
  - 下書きの呼出の行は**字面も並びもそのまま残す**(apply_react_draft.py --stage merge が数と並びを照合する)
  - 呼出の行以外に「呼出」「API」「リクエスト」「fetch」「POST」「GET」の語を書かない(呼出と数えられて割り当てがずれる)
  - 未記入の印「（未記入）この行を…」は残さない
  - **異常系の判断が仕事**: 入力が不正のとき、画面が何をするかをソースから読んで行にする(取得の開始時・成功時・失敗時・0件の行は fact_lines が入るので書かない)
- 下書きが無い画面(HTML)は、イベントごとに呼ぶ API を、ソースの呼出の順に「・<action> をリクエストする」で書く

- イベントが API を 2 つ以上呼ぶときは、下書きの `fetch_plan.mode` を1行で書く。`parallel` なら「…は並行して進める(先の応答を待たない)」、`serial` なら「…の応答を待って…を取得する」(…は業務の語。「リクエスト」「呼出」「API」は入れない)。EV00 の分は S0 が initial_processes に書く
- 連続操作・取得の開始時・成功時・失敗時・0件・CSV の事実の行は、下書きの `event_processes[].fact_lines` と `continuous_operation[].outcomes` からスクリプトが入れる。書かない(書くと同じ文が2つ並ぶ)
- CSV 出力のイベントは、ファイルの中身(列・並び・引用符・合計行・BOM・ファイル名)を details に書かない。下書きの fact_lines(seq)が入る。details に書くのは操作の前提と画面の挙動(押せない条件・読込中の扱い)だけ
- 取消・防止が無いことは、下書きの事実(prevention・fact)をそのまま写す。言い換えて「防げない」などを足さない

- 取得に失敗したときの欄の扱い(何が変わり何が残るか)は、下書きの `event_processes[].fact_lines`(key=failure)に入る。書かない。業務上の意味(利用者に何を見せるか)だけを書く

## 書かない欄
- events の trigger・content(H1)。overview は events の content から作られる
