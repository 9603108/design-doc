# H1 イベントの清書(haiku)

## 入力
- `{機能名}_react_draft.json` の `events`(event_code・trigger・content・classification の下書き)
- screen_config の `screen_name` と `areas[].area_name`

## 書く欄(`_unit_H1.json`。events の行を作る)
- `events[]`: {event_code, trigger, content, classification}
  - event_code・並び・件数は下書きのまま(足さない・減らさない・振り直さない)
  - trigger は「{screen_name}の{エリア名}の{項目}を{動作}する。」の型。先頭は screen_name の字面そのもの
    (「〜画面画面」と重ねない)。初期表示は「{screen_name}の初期表示時」
  - チェックボックス(`<input type="checkbox" onChange>`)の trigger は型が違う。「{screen_name}の{エリア名}の{項目}をチェック、または未チェック。」と書く
    (「する」を付けない。「…をチェックする。」と書かない)。理由: onChange は外す操作でも走るため。型は 02_イベント一覧.md の change(チェックボックス)の行。
    ラジオボタンは「選択」、select は「選択」か「変更」、button 以外の onChange だけの要素に「クリック」「押下」は使わない
    (`verify_vs_source.py` の [イベントの語] が trigger の文もこの型と照合し、外れると H1 へ差し戻す)
  - 動作の語は クリック / 押下 / 変更 / フォーカス外し / チェック / 選択 / 初期表示。onClick・blur などの実装の語は書かない
    (「チェック」はチェックボックスの動作の語で、trigger の文は上の「チェック、または未チェック。」の型にする)
  - content は処理の内容。最初の1文は30字以内
  - classification は「サーバー」(API を呼ぶ)か「クライアント」
  - 下書きの `source` は写さない

## 検査
- `python3 target/scripts/verify_partials.py --units --unit H1`
